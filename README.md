# Videobeaux website

The site at **https://videobeaux.online/** — plain HTML, CSS and JavaScript. No build step, no dependencies. GitHub Pages publishes
this repo's **`v2`** branch (root folder); `CNAME` holds the domain.

```
index.html          the page — all the copy lives here
index_old.html      the previous landing page (kept as a fallback; has noindex)
docs.html           the manual
assets/             images used by the old page and docs.html
site/
├── site.css        styles (colours and fonts are variables at the top)
├── site.js         player, example library, sign-up form
├── assets/         logo, favicon, mascot
├── shots/          app screenshots (made by tools/site-harness/shots.sh in the videobeaux-gui repo)
└── previews/       example clips, posters and examples.json (made by tools/render-site-examples.py in videobeaux-gui)
tools/serve.py      local test server
```

## Work on it

1. Be on `v2` and current: `git checkout v2 && git pull --rebase origin v2`.
2. Preview locally: `python3 tools/serve.py` → http://localhost:8080/ (use this, not `python3 -m http.server`: the examples load with
   `fetch`, and browsers need HTTP Range support to scrub video).
3. Edit, check, then `git add -A`, `git commit -m "…"`, `git push origin v2`.
4. Allow ~2 minutes to build and up to 10 for the cache (`max-age=600`); hard-refresh.

Git uploads only changed files, so a text edit never re-uploads the videos. Re-rendered clips are new binary files and do grow the history —
re-render and push them sparingly.

House style: call them **program modes** (not modules, effects or tools).

## Change the words and links

Edit `index.html`. Sections in order: hero → *Before. After.* player → *For everyone* (3 steps) → *Example library* → *Get Videobeaux*
→ *Stay in the loop*. The two download buttons (`#get`) point at `https://github.com/schwwaaa/videobeaux/releases/latest`; the manual links
at `https://schwwaaa.github.io/videobeaux/docs.html` (and `programs.html`). Colours and fonts: the `:root` block of `site/site.css`.

## The example library and screenshots

These are generated by tools in the **videobeaux-gui** repo (they need the app's program modes), and write straight into this clone:

```bash
# in videobeaux-gui — the clone is found at ../videobeaux-website, or set VB_SITE_DIR
PATH=$PWD/gui/resources/ffmpeg:$PATH python tools/render-site-examples.py     # clips + posters + site/previews/examples.json
tools/site-harness/shots.sh                                                   # canvas.webp, step1–3.webp
```

The list of examples is `tools/site_examples.json` there (one entry per example; several steps = a chain; the first 12 single examples
show before "Show all"). Options: `--only id1,id2`, `--force`, `--jobs 3`, `--site DIR`. Then review, commit and push here. Notes: Auto Narrate
examples need the Vosk model and kokoro-tts installed (skipped with a message otherwise); Remove Background (AI) needs `models/bgremove/`.
The page reads `site/previews/examples.json`, so a new example appears as soon as its `.mp4` and `.jpg` are next to it.

## The sign-up form ("Stay in the loop")

The form on the page posts straight to a **Google Form**, so replies collect in its Google Sheet and visitors never see Google's page.
Everything is set in `SIGNUP` at the top of `site/site.js`:

| Key | What it is |
|---|---|
| `google.form` | the form's responder link (`…/viewform`); used as a "Sign up" button until `google.email` is filled in, and as the fallback if posting fails |
| `google.action` | the same address ending in `/formResponse` |
| `google.email` | field name of the form's **Email** question (`entry.123456789`) |
| `google.interest` | field name of the **Checkboxes** question |
| `google.labels` | the checkbox option text for each choice on the page (must match exactly) |

**In the Google Form:** an *Email* short-answer question (required; Response validation → Email), and a **Checkboxes** question (not Multiple choice)
with the options *Updates and news* and *Join the testing group*. Don't require sign-in and leave "Limit to 1 response" off. On the Responses tab:
*Link to Sheets*, and *Get email notifications*. If you change a question, its `entry.…` name changes — find it by opening the form's responder link,
viewing the page source and searching for `entry.`.

**Security:** no key or password is involved — the form id and `entry.` names are public by nature (anyone can read them in the form's page source).
The page checks the email, ignores a hidden "honeypot" field and instant submits, and Google validates again on its side. Anyone *can* post to a public
Google Form directly, exactly as with the form's own link, so expect the occasional junk row; if spam becomes a problem, move to a provider with
CAPTCHA (Buttondown, Formspree, MailerLite) via `SIGNUP.action`. A Google Form can collect replies but not send mail or unsubscribe people: copy the
addresses into a mailing tool when you start sending updates.

Until `SIGNUP` is filled in the section stays hidden on the live site; on localhost it shows with a note.

## Notes

- Everything the page loads is under `site/`, and `index.html` references it as `site/…`, so the page can sit next to other pages.
- `.gitignore` covers `.DS_Store` and friends. Videos, images and fonts are published content — don't ignore them.
- The dev repo (`schwwaaa/videobeaux`) is separate and has its own Pages site at schwwaaa.github.io/videobeaux/; this repo is what the domain serves.
